# 国心解读 H5（对话版）— 后端接口改动说明

> 依据：[`国心解读H5产品需求文档_V1.1.docx`](./国心解读H5产品需求文档_V1.1.docx)、[`国心解读交互版本`](./国心解读交互版本/)、[`首页`](./首页/) 切图，以及当前 H5 前端已对接约定。  
> 路径前缀与现网一致：`/api/yiqixue/app/guoxin`（下文简称 `{BASE}`）。  
> PRD 中的 `/h5/*` 为业务语义命名；落地时请映射到现网 `{BASE}/*`，**不要**让 H5 直连 Dify。

---

## 1. 总览：产品相对旧版多了什么

| 能力 | 旧版（报告主路径） | 对话版（原型 + PRD） |
|------|-------------------|---------------------|
| 主路径 | 选方向 → 生成报告 | 首页对话问答（Dify 流式） |
| 额度 | 仅报告次数 | **问答次数** + **报告次数**，独立计算 |
| 八字对象 | profiles | 多「八字用户」，会话/报告按 `baziUserId` 隔离 |
| 购买 | H5 微信支付为主 | 套餐确认后 **企微客服** + `scene_param`（仍可保留原支付） |
| 邀请 | 无 | 邀请链接 → 登录 → 填写 → 回流邀请人账号 |
| 反馈 | 无 | 回答「有帮助 / 需改进」 |

**后端至少落库：** 账号、八字用户（含邀请来源/授权）、按 `baziUserId` 隔离的 Dify `conversation_id`、每日问答用量、套餐问答权益、报告额度、报告记录、邀请记录、客服购买上下文。

## 2. 修改 / 扩展现有接口

### 2.1 `GET {BASE}/credits`（必改）

**现状：** 主要返回报告可用次数（`credits` / `availableCount`）。

**改动：** 同一接口同时返回「报告次数」与「问答次数」，前端每次发问前会 **强制刷新** 本接口。

建议响应 `data`：

```json
{
  "credits": 2,
  "availableCount": 2,
  "productId": 1001,
  "chatRemaining": 3,
  "chatUnlimited": false
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `credits` / `availableCount` | number | 是 | **报告**可用次数（兼容旧字段） |
| `productId` | number | 否 | 当前商品/套餐 id |
| `chatRemaining` | number | 是 | **问答**剩余次数（免费日额度或套餐剩余展示用） |
| `chatUnlimited` | boolean | 是 | 套餐期内问答不限次；`true` 时前端跳过「日 3 次用尽」弹窗 |

可选兼容别名（前端已兼容）：`questionRemaining`、`qaRemaining`、`questionUnlimited` 等。

**业务规则：**

- 问答与报告额度独立；普通问答 **不扣** 报告次。
- 问答权益为 **账号级**（多八字用户切换时共用问答次数）。
- 免费用户：每日 3 次，次日 00:00 恢复；套餐不限次时 `chatUnlimited=true`。

> 说明：PRD 另列 `GET /h5/chat/quota`。与前端约定为 **合并进 `credits`**，无需再单独实现 quota 接口（除非后端强拆，则两边需同步改）。

### 2.2 八字用户（profiles）— 建议增强

现有：

- `GET {BASE}/profiles`
- `GET {BASE}/profile/{id}`
- `POST {BASE}/profile`
- `PUT {BASE}/profile/{id}`
- `DELETE {BASE}/profile/{id}`

**建议扩展字段（响应/请求）：**

| 字段 | 说明 |
|------|------|
| `source` | `self` / `invite` 等来源 |
| `relation` | 本人/家人等（现有可保留） |
| `trueSolarTime` / `useTrueSolarTime` | 真太阳时 |
| `birthTimeUnknown` | 时辰不确定（若产品需要） |
| `inviteId` / `authStatus` | 邀请来源与授权状态（被邀请人可撤销） |

**行为：**

- 资料 **修改成功后**，清空该 `baziUserId` 对应 Dify `conversation_id`，下次问答新建会话（避免旧上下文串用）。
- 删除用户时同步清理其会话与授权关系。

> 前端当前仍用 `profiles`；PRD 的 `bazi-users` 可视为同一资源的命名，**不必强制改 path**，字段对齐即可。

### 2.3 报告相关（现有继续用，规则对齐）

现有：

- `POST {BASE}/report/generate`
- `GET {BASE}/task/status`
- `GET {BASE}/report/detail`
- `GET {BASE}/readingRecords`

**改动要点（逻辑，未必改 path）：**

- 报告生成绑定当前 `baziUserId`（profileId）。
- **仅报告成功后**扣 1 次报告额度；失败返还（若已预扣需回滚）。
- 普通问答 **禁止** 走 Dify 报告分支；报告继续原报告服务。
- 生成报告优先复用已保存八字；可附带近期问答摘要/关键词（若产品要「结合问答整理」，建议后续增加上下文入参，见 §4 可选）。

---

### 2.4 商品 / 套餐列表（建议扩展）

现有：`GET {BASE}/products`

**建议扩展展示字段（对齐原型权益页）：**

| 字段 | 说明 |
|------|------|
| 套餐编码 `memberSku` / `skuCode` | 客服 scene 识别用 |
| 名称、现价、原价 | 划线价 + 限时价 |
| 有效天数 / 问答是否不限次 | 对应 `chatUnlimited` 开通结果 |
| 赠送报告次数 | 到账写入报告额度 |
| 是否会员专属（单次加油包） | 非会员拦截 |
| 是否展示倒计时（如 9.9 新人） | 前端展示用 |

购买主路径按 PRD 改为企微客服时，微信支付 `pay/create` 可保留作备用通道。

## 3. 需要新增的接口

### 3.1 流式问答代理（P0，前端已调）

```http
POST {BASE}/chat/messages
Authorization: Bearer {token}
Content-Type: application/json
Accept: text/event-stream
```

**请求体（前端已发送）：**

```json
{
  "query": "最近做决定总犹豫，适合怎么调整？",
  "conversationId": "",
  "conversation_id": "",
  "baziUserId": "档案ID",
  "inputs": {
    "reportTime": 0,
    "bizSource": "guoxin_h5",
    "baziUserId": "档案ID",
    "baziInfo": "姓名 · 性别 · 历法 · 生日 · 地点",
    "relation": "本人",
    "profileName": "姓名"
  }
}
```

> `baziInfo` 正式联调建议改为 PRD JSON 结构（见 §5）；前端可再对齐。当前为可读摘要字符串。

**后端处理顺序：**

1. 鉴权；校验 `baziUserId` 属于当前账号且资料可用。  
2. 校验 **问答权益**（无次数 → 拒绝；建议 HTTP `429` 或业务码 + 文案含「次数/用完」）。  
3. 读取该用户已存 `conversation_id`（无则空串）。  
4. 代理 Dify `POST .../v1/chat-messages`，`response_mode=streaming`；`user` 建议 `gx_{appUserId}_{baziUserId}`。  
5. 将 SSE 转发给 H5；解析并回传 `conversation_id` / `message_id`。  
6. **收到结束事件并落库后** 扣 1 次问答；失败 / 超时 / 客户端中断 **不扣**。

**SSE 约定（前端可解析）：**

- `Content-Type: text/event-stream`
- `data:` 行为 JSON，增量/累计文本字段之一：`answer` | `content` | `delta`
- 会话 id：JSON 内 `conversation_id` / `conversationId`，或 `event: session` + data 为 id
- 结束：`message_end` / `workflow_finished` / `data: [DONE]`
- 错误：`event: error` 或 JSON `event`/`status` = `error`

也可用整包 `application/json` 兼容（前端已支持），但产品要求流式体验，**优先 SSE**。

### 3.2 邀请好友填写（P1）

| 方法 | 路径建议 | 说明 |
|------|----------|------|
| `POST` | `{BASE}/invitations` | 生成 `inviteToken` + 分享链接；单次有效、可配置有效期（默认 7 天） |
| `GET` | `{BASE}/invitations/{token}` | 校验状态（未登录可返回需登录）；**URL 不带八字明文** |
| `POST` | `{BASE}/invitations/{token}/accept` | 被邀请人登录后提交八字并授权；在 **邀请人账号** 下创建八字用户，`source=invite` |

**规则：** 先登录再填写；可撤销授权；撤销后邀请人不可再用于问答/报告。

---

### 3.3 企微客服购买上下文（P1）

| 方法 | 路径建议 | 说明 |
|------|----------|------|
| `POST` | `{BASE}/customer-service/context` | 用户点「联系客服购买」时写入购买上下文，返回可放入 `scene_param` 的短令牌（≤128 字节，URL 编码） |
| `POST` | `{BASE}/customer-service/callback` | 企微客服事件回调；用 `scene_param` 查出套餐名称、价格、来源、`memberSku`、`baziUserId` 等 |

**跳转：** 使用企业微信「获取客服帐号链接」生成的专属链接；**不要**在 URL 中传手机号/八字明文。

上下文建议字段：`memberSku`、套餐名、现价/原价、有效天数、赠送报告次数、`appUserId`、可选 `baziUserId`、来源（如 `paywall` / `quota_empty`）。

## 8. 联调验收清单

- [ ] `credits` 同时返回报告次与问答次；问成功一轮后仅问答侧变化  
- [ ] 问答失败/超时/取消不扣问答次；成功结束才扣  
- [ ] 免费日 3 次，次日恢复；`chatUnlimited` 时前端不弹日限额用尽  
- [ ] 同一 `baziUserId` 连续追问共用 `conversation_id`；切换用户不串会话  
- [ ] 修改八字资料后该用户会话重建  
- [ ] H5 请求中 **无** Dify API Key  
- [ ] 报告成功才扣报告次；问答不扣报告次  
- [ ] 邀请链接无明文八字；接受后用户出现在邀请人列表  
- [ ] 客服 `scene_param` 可还原套餐意向且 ≤128 字节
